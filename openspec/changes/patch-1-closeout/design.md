## Context

См. `proposal.md` — Why. Существенное для подхода:

- **Источники приёмки лежат вне репозитория и read-only.** `verify-prototypes.py` (74 проверки) и `audit-pages.py` (постраничный отсмотр 15 макетов) живут в `../zazemli-vault/Айти/Сайт/`. В CI и в ночном раннере vault не склонирован.
- **Оба скрипта проверяют прототипы, а не сборку.** Патч требует прогнать те же проверки по собранным страницам: «Скрипты проверяют прототипы. После переноса в Next.js прогони те же проверки по собранным страницам, часть регулярок применима напрямую» (§7.1).
- **Прецедент уже выбран.** `src/app/page.built.test.ts` переложил применимые проверки на `out/index.html` и карточки SKU; эталонные тексты прототипов не читаются из vault на лету, а коммитятся в `src/content/__fixtures__/` генератором `npm run extract:prototypes`.
- **Сборка статическая** (`output: "export"`), `out/` в git не попадает и появляется только после `npm run build`.

## Goals / Non-Goals

**Goals:**
- Приёмка PATCH-1 §7 воспроизводится одной командой и не зависит от наличия vault.
- Покрытие built-проверками распространяется с главной и карточек на все 15 макетов.
- Результат ручных приёмок §7.2–7.3 зафиксирован доказательством, а не отметкой «посмотрел».

**Non-Goals:**
- Не переписываем и не «улучшаем» сами python-скрипты в vault — он read-only, синк односторонний.
- Не гоняем python из тестов: приёмка должна работать там, где vault недоступен.
- Не превращаем приёмку в пиксельную сверку с прототипом — сборка на Tailwind, разметка заведомо другая.

## Decisions

**D1. Проверки переносятся в vitest по `out/`, а не вызывают скрипты vault.**
Альтернатива — дёргать `python3 verify-prototypes.py` с путём на `out/` — отпадает по двум причинам: скрипты разбирают структуру прототипа (свои классы, самодостаточные файлы), и в CI/ночью vault отсутствует, так что гейт был бы зелёным просто от того, что нечего запускать. Тот же выбор уже сделан для эталонов текста.

**D2. Переносится контракт, а не разметка.**
Критерий применимости проверки: она про **содержание и обещания страницы** — цены, состав бокса, запрещённая лексика, юр-строки и реквизиты, `noindex`/`canonical`, отсутствие плейсхолдеров и битых ссылок, verbatim-тексты согласий и cookie-нотиса. Проверки про классы и структуру прототипа (`.split`, `.boxsec`, порядок узлов) не переносятся: в сборке их эквивалент — Tailwind-грид, и буквальная регулярка дала бы ложное падение. Патч это допускает прямо — «часть регулярок применима напрямую», а не все.

**D3. Built-приёмка разделяется по роутам.**
Сейчас всё лежит в `src/app/page.built.test.ts`. Добавление восьми страниц в один файл сделает его нечитаемым, а падение — неадресным. Раскладываем по страницам рядом с роутом (`src/app/<route>/*.built.test.ts`) с общим хелпером чтения `out/`; существующий файл не переписываем, только выносим из него общий доступ к сборке.

**D4. Ручные приёмки автоматизируются настолько, насколько поддаются.**
§7.2: имя voice-файла с `mulish` в `out/_next/media/`, отсутствие `fonts.googleapis.com` в разметке и отрицательный трекинг заголовков — проверяются по сборке. §7.3: cookie-сценарий (появление → выбор → не возвращается, до «Принять все» нет запросов к `mc.yandex.ru`) — e2e Playwright, инфраструктура уже есть. Глазами остаётся ровно одно: различим ли стык h2 → body. Патч на этом настаивает отдельно, потому что оба шрифта теперь гротески.

**D5. Находка чинится здесь только в границах действующих спек.**
Если приёмка вскрывает расхождение с уже описанным поведением — правим в этом change. Если находка требует нового требования — заводим отдельный change. Иначе closeout превратится в свалку и никогда не закроется.

**D6. Приёмка идёт до `typo-scale`.**
FIX-15 переверстает шкалу кеглей; если гнать приёмку после него, она поедет по изменённой типографике, и разделить «сломал FIX-15» и «не доехало из патча» будет нечем.

## Risks / Trade-offs

- **Built-тесты мягко скипаются без `out/` → зелёный прогон ничего не доказывает.** → Приёмка засчитывается только по выводу, где видно, что блоки выполнены, а не пропущены; в чек-лист входит `npm run build` перед прогоном.
- **Эталоны в `__fixtures__` расходятся с vault после его обновления.** → Фиксируем в отчёте коммит vault, по которому шла приёмка (сейчас `311ab66`, прототипы не менялись с 01.08), перегенерация — `npm run extract:prototypes`.
- **Соблазн перенести все 74 проверки буквально** даст ложные падения и подорвёт доверие к гейту. → Критерий D2 применяется к каждой проверке осознанно; непереносимые фиксируются списком с причиной, а не молча выбрасываются.
- **Находок может оказаться много, и часть — не наша** (канон против прототипа против прода). → Порядок старшинства уже задан BUILD-SPEC: свежее решение Насты → канон `.md` → прототип → живая сборка. Спор по существу уходит Насте, а не решается в коде.
- **Закрытие цикла волны — не работа агента.** `verify`, `review`, `sync`, `archive` запускает владелец; в `tasks.md` они отдельным блоком, чтобы ночной раннер их не подхватил.
