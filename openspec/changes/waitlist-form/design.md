# waitlist-form — design

## Context

Формы N°08 в коде нет; плитка N°08 в галерее — статичное приглашение (после `home-restructure` — место зарезервировано). PATCH-1 §3 задаёт механику (шаг 2 в попапе — NEW-02), русский язык без склонений (NEW-05), юр-конструкцию «не рассылка» (NEW-07, P0) и контракт бэкенда (FIX-73, P0). Сайт — static export; серверной части нет, решение по серверу (VPS) принимается отдельно.

## Goals / Non-Goals

**Goals:**
- Собрать UI формы и попапа целиком по эталону `#waitModal` с a11y и пятью состояниями.
- Зашить юр-тексты verbatim и события Метрики.
- Определить контракт API и защитить включение фича-флагом.

**Non-Goals:**
- Реализация `/api/waitlist/*`, лог согласий, интеграция Sendsay — отдельный change (`waitlist-api`) после решения по серверу.
- Изменения `/diary-signup` («Дневник растения» — отдельная база, конструкция не менялась).
- Операционные ограничения Sendsay (по базе «Лист ожидания» — ровно одно письмо, без промо: письмо держать информационным — риск переквалификации в рекламу по 38-ФЗ; флаг юристу при sign-off).

## Decisions

1. **Нативный `<dialog>` + `showModal()`**, не самодельный оверлей: патч прямо требует, эталон разметки — `#waitModal` в `landing.html`. Фокус-ловушка и Esc у `showModal()` нативные; остаётся клик-по-фону, возврат фокуса и крестик 44×44.
2. **Никаких склонений**: правило «-а → -у» ломается на «фикус Бенджамина» — название рендерится как введено, тексты сконструированы без падежей (в каноне уже переписаны все четыре места). Обрезка ввода до 42 знаков — на шаге 1.
3. **Фича-флаг по образцу diary-signup** (`wrap submit in POST integration point behind flag`, коммит `de51848`): единый паттерн интеграционных точек в проекте. При выключенном флаге запросы не уходят; сбор не публикуется — лог согласий (≥ 3 лет) есть условие законности, а не доработка.
4. **Шаг 1 пишет растение до почты** (контракт): даже брошенный шаг 2 сохраняет спрос — `waitlist_plant_input` с свойством `plant` плюс серверный счётчик; это единственный источник данных для следующей партии.
5. **Стили плитки не протекают в форму** (NEW-01): селектор карточек галереи ограничен карточками ещё в `home-restructure`; служебные ссылки в чекбоксах попапа стилизуются собственными классами.

## Risks / Trade-offs

- Форма без бэкенда — «неживой» UI за флагом: осознанно; включение синхронизируется с `waitlist-api` и sign-off юриста.
- `<dialog>` в static export рендерится после гидрации — шаг 1 деградирует изящно (кнопка неактивна до готовности JS).
- Поле `consent_ads` в контракте — имя из канона (историческое); семантика — согласие на письмо, не на рекламу; не переименовывать без правки канона.
