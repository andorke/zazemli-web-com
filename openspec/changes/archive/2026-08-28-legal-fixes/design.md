# legal-fixes — design

## Context

Прод собран по устаревшему юр-канону: адрес ИП попал в `privacy.ts` из `PDN-152FZ-SPEC §4a` (в актуальных прототипах адреса нет ни в одном файле — PATCH-1 FIX-01, P0), `/privacy` — редакция из 11 разделов при канонных 13, `/terms` не собран вовсе (FIX-08). Consent-механика на проде правильная по поведению (гранулярный баннер, гейт Метрики — PATCH-1 прямо запрещает её откатывать), но значения ключа расходятся с каноном.

## Goals / Non-Goals

**Goals:**
- Убрать утечку адреса; исключить её возврат (тест по `src/` и `out/`).
- Довести юр-контур до канона: `/terms`, редакция `/privacy`, состав футера, consent-значения.

**Non-Goals:**
- Юр-конструкция формы N°08 «не рассылка» — в change `waitlist-form`.
- UTM на соцссылки — в `seo-meta` (здесь только «не ложные ссылки»).
- Sign-off юриста (внешний процесс; см. открытый вопрос в CONTEXT.md про `/privacy`).

## Decisions

1. **Тексты переносим из прототипов дословно** (`terms.html`, свежий `privacy.html`), правило источников PATCH-1 §0: свежее решение Насты → канон `.md` → прототип → прод. Никакого редактирования юр-формулировок на стороне сборки.
2. **`/terms` строим по образцу `/privacy`**: контент-модуль `src/content/terms.ts` + typography-first страница вне DS. Альтернатива (общий «юр-шаблон» компонентом) отклонена: две страницы, преждевременная абстракция.
3. **Consent: маппинг легаси при чтении, запись — только новые значения.** `getConsent()` читает `granted→all`, `denied→necessary`; тип меняется на `'necessary' | 'all'`. Альтернатива (одноразовая миграция записи) отклонена: чтение-маппинг проще и не требует side-effect при загрузке.
4. **Проверка адреса — регресс-тест**, а не разовая правка: контент-тест ищет маркеры адреса (`Ковров`, `Строителей`) по `src/content` и собранному `out/` — чтобы утечка не вернулась при следующем переносе канона (патч требует «понять, откуда взялся, чтобы не вернулся» — источник: старый канон, механизм возврата — копирование из PDN-152FZ-SPEC).

## Risks / Trade-offs

- Смена типа `Consent` затрагивает подписчиков `useConsent` (Метрика, баннер) — правка сквозная, но маленькая; компенсируется тестами баннера.
- Редакция `/privacy` 11→13 разделов может сломать существующие контент-тесты со списком разделов — обновляются вместе с текстом.
- Тексты ждут sign-off юриста (внешний блокер запуска сбора email, не этой работы).
