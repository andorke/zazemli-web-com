# patch-1-closeout

## Why

Волна PATCH-1 выкачена на прод 03.08, но **приёмка самого патча закрыта частично**, и это не формальность: патч прямо предупреждает, что прошлая итерация сорвалась именно на сверке — правка стояла ✅ в отчёте, а в файле её не было. Сейчас §7.1 переложен на сборку только для главной и семи карточек (`page.built.test.ts`), постраничный `audit-pages.py` по `out/` не гонялся вовсе, а обе ручные приёмки (§7.2–7.3) висят открытыми задачами в `font-mulish` и `legal-fixes`. Параллельно пять реализованных changes волны не прошли `verify → review → sync → archive`, поэтому их delta-спеки не доехали до `openspec/specs/` — следующая волна поедет от неточного канона.

## What Changes

- **Приёмка §7.1 распространяется на остальные страницы сборки**: `/guide` ×3, `/lab`, `/diary-signup`, `/privacy`, `/terms`, `/collectio` — сейчас built-проверки знают только главную и карточки SKU.
- **Постраничный отсмотр `audit-pages.py` перекладывается на `out/`**: применимые проверки скрипта становятся частью built-приёмки, «на что смотреть» должно быть пустым по всем 15 макетам.
- **Ручные приёмки закрываются с зафиксированным результатом**: §7.2 (шрифт — `mulish` в `/_next/media/`, Network пуст по `fonts.googleapis.com`, отрицательный трекинг, различимый стык h2 → body) и §7.3 (cookie: появление → выбор → не возвращается; до «Принять все» нет запросов к `mc.yandex.ru`).
- **Найденные расхождения чинятся** в границах уже описанного поведения; всё, что тянет на новое требование, выносится отдельным change, а не дописывается сюда.
- **Цикл волны закрывается** — `verify → review → sync → archive` по пяти changes. Это владельческие команды, они вынесены в `tasks.md` отдельным блоком и агентом не запускаются.

**Не входит:** бэкенд листа ожидания (`/api/waitlist/*`, лог согласий, Sendsay) — отложен решением владельца, форма N°08 остаётся выключенной флагом; схлопывание типо-шкалы FIX-15 — отдельный change `typo-scale`; девять открытых задач `qr-welcome`.

## Capabilities

### New Capabilities

_нет_

### Modified Capabilities

_нет_ — change целиком про приёмку и тестовую оснастку: продуктовое поведение описано действующими спеками и не меняется. `.openspec.yaml` помечен `skip_specs: true`. Если ручная приёмка вскроет расхождение, которое требует нового требования, оно уходит отдельным change — выдумывать requirement ради валидации нельзя.

## Impact

- `src/app/page.built.test.ts` (расширяется на остальные роуты либо разделяется по страницам), возможные точечные починки контента и разметки по находкам.
- Источники приёмки — read-only во внешнем vault: `../zazemli-vault/Айти/Сайт/verify-prototypes.py`, `audit-pages.py`, `PATCH-1-2026-07-30.md` §7. В CI и ночной сборке vault недоступен, поэтому проверки живут в репозитории, а не вызывают скрипты напрямую — тот же приём, что уже выбран для эталонов `extract:prototypes`.
- Требует свежей сборки (`npm run build`): built-тесты мягко скипаются без `out/`, и «зелено» без сборки ничего не доказывает.
- Пересечений с `typo-scale` нет по коду, но есть по порядку: FIX-15 переверстает шкалу кеглей, поэтому приёмку логично закрыть до него — иначе она поедет по уже изменённой типографике.
