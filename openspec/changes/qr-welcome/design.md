## Context

QR партии 0 напечатаны на пачках с чистыми путями (`/guide`, `/lab`, `/collectio`, страница III печатного дневника → `/diary-signup`). Сайт — статический Next.js 16 export, motion-правила жёсткие («MVP без анимации», только CSS + vanilla IntersectionObserver, composited-свойства). Решения владельца (интервью 2026-08-01): заметная хореография с точечными исключениями, флагман `/guide`, встреча collectio-входа на главной, курсор-компаньон «кольцо мха». Выбор вариантов: «Путь пяти шагов» (/guide), «Рецепт собирается» (/lab), «Каскад снизу» (коллекция), «Разворот письма» (/diary-signup).

Ресерч-базис (4 deep-research прогона, август 2026): каталог CSS-only entrance-техник с браузерной поддержкой; QR-паттерны прибытия (скан не даёт referrer; скан камерой = новая вкладка = пустой sessionStorage; анти-паттерны NN/g/Google — только инлайн, без оверлеев); архитектура cursor-слоя (rAF+lerp, пул частиц, pointercancel); референсы (108 Supply, HX Clinic, Dense Discovery, Materra).

## Goals / Non-Goals

**Goals:**
- Entrance-встреча на 4 QR-входах по выбранным вариантам, show-once за вкладку.
- Cursor-companion «кольцо мха» + click-burst + tap-ripple.
- Ноль новых зависимостей, ноль деградации мобильного LCP, ds-lint зелёный.
- Все исключения из «MVP без анимации» зафиксированы дельтой спеки design-system.

**Non-Goals:**
- Аналитика сканов и UTM-разметка (capability analytics-consent — отдельно).
- Конвенция QR будущих партий `/p/<sku>` (отдельный change; здесь только зарезервирован `?src=qr`).
- View Transitions между страницами, SVG-морфинг «роста», WebGL.
- Изменение контента/структуры страниц (страничные спеки не трогаем).

## Decisions

### D1. Show-once: класс на `<html>` до первой отрисовки
Инлайн-скрипт в `<head>` (raw `<script dangerouslySetInnerHTML>` в `layout.tsx` — `next/script beforeInteractive` не гарантирует выполнение до пейнта): try/catch чтение `sessionStorage`, при отсутствии флага — `documentElement.classList.add('js-welcome')` + запись флага. Все entrance-стили — только под `html.js-welcome` и `@media (prefers-reduced-motion: no-preference)`.
**Почему не альтернативы:** `@starting-style` без классового гейта не даёт show-once и мигает на повторных заходах; чистый IO-подход прячет контент до гидратации (риск невидимого контента при медленном JS). Классовый гейт решает FOUC, no-JS и reduced-motion одним механизмом.
**Следствие QR-механики:** скан камерой открывает новую вкладку → sessionStorage пуст → встреча на каждый скан; внутренняя навигация — без повторов. Это желаемое поведение.

### D2. Каскад: `@keyframes` + `animation-delay` лесенка, stagger через `:nth-child`/явные классы
Универсальная поддержка, `animation-fill-mode: both` держит стартовое состояние на время делея. Элементы hero разнородны и статичны (4–5 штук) — явные задержки/nth-child проще, чем `--index` в разметке. `sibling-index()` отложен (нет Firefox).

### D3. Тайминги — временный дефолт из DS-токенов, всё через CSS-переменные
Элемент каскада: `--duration-slow` (400ms), шаг лесенки 80ms, easing `--ease-emphasized`; масочный вылет строк: `--duration-page` (600ms). Открытый вопрос дизайнера (прототипные 700–900ms и кривая `.22,1,.36,1` vs канон ≤500ms и DS-кривая) не решается здесь: все значения выводятся в переменные `--welcome-*` в одном блоке `globals.css` — решение Насти правится в одном месте.

### D4. Масочный вылет строк h1 (/guide) — только на десктопе, мобайл упрощён
Строки заголовка — фиксированные обёртки-спаны (переносы контролируются контентом, не автопереносом). Маска `overflow: hidden`, вылет `translateY(110%→0)` — исключение, зафиксированное в дельте DS. **LCP-защита:** на мобиле (известное слабое место, LCP ~8.8s) масочный вылет отключён — h1 получает только лёгкий `translateY` ≤10px с `opacity` от 0.1 (не 0: элемент с `opacity: 0` выпадает из LCP-кандидатов Chrome). Маска включается с брейкпоинта `lg`.

### D5. Прорисовки линий и полосок — только `transform: scaleX`
Линия стадий /guide и полоски долей /lab: элемент статичной ширины (доля в %), анимируется `scaleX(0→1)` c `transform-origin: left`. Гарантированный компоузинг; `width`-transition (как у референсов Canopy/Materra) запрещён списком notAnimatable. Расходование clip-path отклонено (не гарантированно композитится; выбранный вариант коллекции его не требует).

### D6. Каскад коллекции: hash-триггер + IO-фоллбэк
Клиентский эффект в SkuGallery: при монтировании читает `location.hash === '#collectio'` → мгновенный запуск каскада (секция уже в вьюпорте после якорного позиционирования); иначе — стандартный IO-триггер при доскролле. Редирект `/collectio` не меняется.

### D7. Cursor-companion: один клиентский компонент в layout
Архитектура из ресерча: слой `position: fixed; inset: 0; pointer-events: none; aria-hidden`; follower — кольцо мха 10–12px, `pointermove {passive: true}` пишет координаты, rAF-цикл lerp ~0.15 применяет `translate3d`, остановка цикла при дельте <0.1px; `will-change` только на кольце. Клик/тап-эффекты — пул из 8 элементов, возврат по `animationend`, константный радиус. Гейт: CSS `@media (hover: hover) and (pointer: fine)` + рантайм `pointerType === 'mouse'` (гибриды: тач не показывает кольцо). Декоративные зоны размечаются `data-fx` на секциях (hero, повествование); guard `event.target.closest('a,button,input,label,summary,form')` → эффект не спавнится. `pointercancel` гасит рябь при скролле. Reduced-motion: matchMedia-проверка + подписка на change, слой не монтируется.

### D8. Никаких новых зависимостей, ds-lint нетронут
Весь слой — CSS + vanilla JS. Grain/цвета — только токены (никаких hex в `.tsx`). Тени и радиусы не используются. Существующий глобальный reduced-motion блок в `globals.css` остаётся; новые анимации дополнительно живут под `no-preference` (двойная защита).

## Risks / Trade-offs

- [Масочный вылет строк сдвигает LCP на guide] → мобайл-фоллбэк без маски (D4), `opacity` от 0.1, замер Lighthouse mobile до/после в задачах; при деградации >0.2s маска отключается и на десктопе.
- [Строки h1 «плывут» при ресайзе/догрузке шрифта] → переносы фиксированы в контент-файле (спаны), voice-шрифт уже preload; маска на блок строки, не на визуальную строку автопереноса.
- [sessionStorage недоступен (приватные режимы/webview)] → try/catch, деградация «показывать встречу» (D1).
- [Каскад секций ниже фолда виден не будет, усилия впустую] → каскады ниже фолда триггерятся IO при реальном появлении, а не по таймеру.
- [Cursor-burst перехватит клик по CTA] → `pointer-events: none` на слое + guard по closest (D7); e2e-проверка клика по OzonButton при активном слое.
- [Лесенка задержек на слабых телефонах] → только opacity/transform, максимум 7 одновременных элементов (карточки), шаг 70–80ms — суммарно <1s; in-app браузеры холодные, но вес не растёт (0 зависимостей, только CSS/JS ~3–4КБ).
- [Расхождение с будущим решением Насти по таймингам] → все значения в `--welcome-*` переменных, правка в одном месте (D3).

## Migration Plan

Обычный статический деплой (`npm run build` → `out/`). Отката фичи достаточно на уровне revert-коммита; аварийное отключение хореографии возможно удалением инлайн-скрипта (класс не ставится → встречи нет, контент полностью видим). Данные не мигрируют.

## Open Questions

- Формулировка h1 `/guide` = дословная фраза с пачки («рукопожатие» из ресерча): сверить текст напечатанной партии 0 с `guide.hero.title` — правка контента, не кода.
- Печать будущих партий (`/p/<sku>` + UTM на развороте) — отдельный change после решения по хостингу.
